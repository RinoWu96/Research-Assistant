# V0.7.1 Release and Windows Packaging

V0.7.1 freezes the usable V0.7 scientific evidence workflow without changing
retrieval, ranking, classification, citation verification, paper identity,
semantic indexing, or Evidence Report semantics.

## Windows portable bundle

```powershell
py -3.12 -m venv .venv-build
.\.venv-build\Scripts\python.exe -m pip install -r requirements-build.txt
.\packaging\build-windows.ps1
```

The release build is intentionally reproducible on official CPython 3.12 with
PySide6 6.8.3. Newer Qt wheels are not used for this frozen Windows artifact
because their MSVC runtime layout is incompatible with the validated PyInstaller
bundle on the release host.

The versioned ZIP is written to `release/`. The unpacked folder contains:

- `ResearchAssistant.exe`: windowed desktop GUI and thin Core client;
- `ResearchAssistantCore.exe`: persistent Core hosted in the Windows system tray;
- `ResearchAssistantMCP.exe`: stdio MCP proxy to the same Core;
- `_internal/`: shared packaged Python dependencies.

Closing the GUI does not stop the Core. The Core tray menu opens a new GUI or
explicitly exits the Core. Single-instance locking remains owned by the Core.

Frozen builds store mutable data under
`%LOCALAPPDATA%\ResearchAssistant\data`. Development builds retain the repository
`data/` default. `RESEARCH_ASSISTANT_DATA_DIR` overrides either default.

## Release verification

Before tagging, run the complete suite, build the ZIP, start the packaged Core
against real data, confirm tray/Core/embedding readiness, confirm the packaged
GUI reuses that PID, run a real evidence query, perform an MCP stdio handshake,
and record the ZIP SHA-256.

The bundle contains no Zotero library, PDFs, application database, semantic
index, model cache, credentials, or MCP client configuration.
