# V0.2 semantic integration plan

V0.1 remains the source of truth. SQLite stores original PDF page text and paper
metadata; FTS5 continues to provide strict keyword results. The optional semantic
layer reads those pages, creates deterministic page-local chunks, embeds the chunks
on CPU and maps FAISS vector IDs back to stable source identifiers. Result text is
always fetched from or directly sliced from the original PDF extraction data.

```text
SQLite pages -> deterministic chunker -> local embedder -> FAISS
     |                                             |
     +-------------- original source lookup <-----+
```

The proof of concept uses 5-10 already indexed papers, an exact inner-product FAISS
index over normalized vectors (cosine similarity), and temporary metadata. It does
not change SQLite, write the production `data/vectors/` directory, contact Zotero,
or modify the GUI. `BAAI/bge-small-en-v1.5` is loaded lazily on CPU. The model may be
downloaded once from Hugging Face; inference and subsequent cached use are local and
require no paid service.

## V0.2b persistent backend

The production backend is now implemented under `data/semantic/`:

- `chunks.sqlite` caches chunk coordinates and float32 embeddings. It deliberately
  does not duplicate page text or bibliographic metadata.
- `index.faiss` is an exact cosine-similarity index with stable chunk IDs.
- `index_metadata.json` records model, dimension, chunker version/settings, build and
  update timestamps, corpus counts and an atomic generation ID.

`literature.db` remains authoritative. Search resolves a FAISS chunk ID through its
page ID and character offsets, then slices the current original page text. Model output
is never displayed as source text.

Incremental updates compare each paper's sorted attachment content signatures and
metadata/collection signature. New and content-changed papers are embedded; unchanged
papers skip; metadata-only changes do not call the model; removed papers lose cached
chunks. FAISS mutation is intentionally avoided: after vector membership changes, a
new exact index is built from cached embeddings and atomically replaces the old file.
Unchanged document embeddings are never recomputed. A generation marker detects a
crash or interruption between cache and FAISS replacement.

Model, dimension, chunker version, target size and overlap are compatibility keys.
An incompatible index raises `SemanticRebuildRequired`; only the explicit
`semantic-index --rebuild` command discards cached embeddings.

Semantic filters build a temporary exact FAISS view from eligible cached vectors, so
collection/year/journal restrictions are applied before ranking. Unfiltered queries
use the persistent FAISS index. Overlapping near-duplicates are removed and results
are round-robin diversified, with two chunks per paper by default.

`UnifiedSearchService` supports keyword, semantic and hybrid modes plus chunk/paper
result levels. Hybrid ranking uses RRF over ranks, never raw BM25/cosine arithmetic.
Paper scores are the best chunk plus 25% of the second-best, retaining explicit keyword
and semantic evidence flags. Hybrid catches semantic-index errors and returns keyword
results; strict keyword search therefore remains independent.

GUI integration remains deliberately deferred until retrieval quality is approved.
