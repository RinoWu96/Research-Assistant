# V0.7.2 Incremental Updates and Supporting Information

V0.7.2 makes library updates work again on current Zotero builds, updates the
keyword and semantic indexes in one step, and indexes supporting-information
PDFs. Retrieval, ranking, classification and citation verification are
unchanged.

## Incremental updates

- **Zotero source identity.** Zotero 7+ sends a `Zotero-Server-ID` header. An
  index bound to the older fallback identity (`local-personal-library`) now
  adopts the real ID in place instead of rejecting every update as a different
  library. A genuinely different Zotero source is still refused.
- **Timeouts.** The connect timeout stays at 5 s, so a missing Zotero still
  fails fast. Reads may take up to 300 s, because Zotero resolves attachment
  files while it lists them and that is slow when storage is on a cloud drive.
- **Fewer items listed.** Whole-library listing excludes annotations on the
  Zotero side. Annotations are skipped during indexing anyway.
- **One update for both indexes.** The GUI incremental update, Full Rebuild,
  and CLI `index` / `rebuild` now bring the semantic index up to date right
  after the keyword index. `semantic-index` remains available for semantic-only
  maintenance, for example `--rebuild` after a model change.
- **Live paper count.** The Core `/status` paper count is now read from the
  database on each request. It follows index updates without restarting the
  Core.

## Supporting information

- **Discovering SI.** PDFs saved into a stored attachment's Zotero storage
  folder without being registered in Zotero are indexed as supplementary
  attachments of the same paper, keyed `<KEY>-SI-<hash>`. Only Zotero-managed
  folders, named after the attachment key, are scanned. Linked-file
  directories are not. Zotero is never modified.
- **Registered SI.** Zotero attachments named like publisher SI files
  ("Supporting/Supplementary Information", `_si_001`, `MOESM`, `mmc1`,
  `suppmat`, `_sm.pdf`) are flagged too. A bare "SI" is deliberately not
  matched, so author names and silicon do not trigger it.
- **Renamed main text.** If Zotero's recorded file is missing and the storage
  folder holds exactly one PDF, that PDF is read as the main text.
- **Flag in the outputs.** The flag is stored in `attachments.supplementary`, an
  additive migration. It is carried into evidence packs, evidence reports and
  the MCP provenance (`supplementary: true|false`), so a passage from an SI is
  never presented as main-text evidence.

## Packaging

`packaging/build-incremental.ps1` rebuilds with PyInstaller's cache. When
`_internal` is unchanged, it replaces only the three executables in the
existing portable bundle; system runtime DLL differences are ignored. If
dependencies changed, it stops and asks for a full `build-windows.ps1`.

Both build scripts and the spec read the version from `app/version.py`.
